## Проект в двух словах

- `PGN Spy/` — GUI на MFC (Windows). Запускает `pgn-extract.exe` и `uci-analyser.exe`, считает T1/T2/T3 и потери в сотых пешки.
- `uci-analyser/` — консольная программа. Гоняет UCI-движок (Stockfish) по партиям, пишет XML.
- Сборка только под Windows (VS 2022, v143, MFC). Здесь, в облаке, собрать GUI нельзя.

## Баги (по важности)

1. ✅ **Сторож движка не убивает зависший движок** — `uci-analyser/engine.cpp`, `EngineMonitorStatic`.
   Зовёт `quitEngine()` из своего же потока.
   Тот ждёт сам себя 30 с (`WaitForSingleObject(hEngineMonitor)`), шлёт `quit` зависшему движку и закрывает трубы.
   Движок жив, основной поток висит в `ReadFile` навсегда. В GUI партия не завершается никогда.
   Фикс: в стороже делать `TerminateProcess(m_hEngineProcess)`, а не `quitEngine()`.
2. ✅ **Ошибка приоритета операторов в «после проигрыша»** — `PGN Spy/ResultsDlg.cpp:340-341`.
   `!Excluded && (white && W) || (!white && B)` — для чёрных проверка «позиция мёртвая» пропускается.
   Статистика POST-LOSING для чёрных портится. Нужны скобки.
3. ✅ **Ход не найден → засчитывается как T1** — `PGN Spy/Analysis.cpp`, `CGame::LoadGame`.
   `m_iMovePlayed` по умолчанию 0. Если сыгранного хода нет среди оценок, он считается лучшим ходом с потерей 0.
   Для инструмента ловли читеров это завышает совпадения. Надо ставить -1 и пропускать позицию.
4. ✅ **Ошибки анализатора не ловятся** — `PGN Spy/AnalysisDlg.cpp:667`.
   `iExitCode < 0` для `DWORD` всегда ложь. Коды -1/-2 от анализатора игнорируются.
5. ✅ **Потеря партии из-за stderr** — `AnalysisDlg.cpp:675-682`.
   Если в stderr есть данные, функция читает их и выходит, не читая stdout. На последнем вызове партия теряется.
6. ✅ **Экспорт PGN ломается на партиях с FEN** — `Analysis.cpp`, `BuildAnnotatedUCIGameText`.
   Анализатор для FEN не пропускает дебют, а экспорт пропускает. Позиции не совпадают — падает экспорт всего файла.
7. ✅ **XML не экранирует `<` и `>`** — `uci-analyser/analyse.cpp`, `outputTag`.
   Тег вроде `[Event "U<18"]` даёт битый XML → партия считается ошибочной.
8. ✅ **Кодировка** — всё читается/пишется в `CP_ACP`.
   PGN в UTF-8 (lichess, chess.com) с кириллицей → кракозябры, фильтр по имени игрока не срабатывает.
9. **Выход за границы массива** — `analyse.cpp`, `extractInfo`.
   Если в строке `info` нет `time` (или `depth` последний), читается `infoTokens[size]`. Stockfish так не пишет, другие движки могут.
10. **Утечка памяти** — `analyse.cpp`, `saveEvaluation`: старая оценка удаляется из вектора без `delete`.
11. **`unsigned` вместо `size_t`** — `analyse.cpp`, `extractTagValue`: на x64/Linux сравнение с `npos` всегда истинно.
12. **Linux-сборка сломана** — `engine.h/.cpp` используют `HANDLE`, `WaitForSingleObject` вне `#ifdef`. `make` не собирается.
13. **`-s` теряется у pgn-extract** — `Analysis.cpp`, `RunConverterToSAN`: первый токен командной строки съедается как argv[0].
    Там же причина хака `argnum = 0` в `analyse.cpp`. Лучше всегда передавать путь к exe первым аргументом.
14. **Версии разъехались** — релиз v1.2.2, а `app.manifest` и `PGN Spy.rc` = 1.2.1.0. `analyse.cpp` VERSION = 2014.06.02.
15. **`PGN Spy.aps` в git**, хотя `*.aps` в `.gitignore`. Это бинарный кэш VS.

## Мелочи

- `EscapeCmdArg` по сути ничего не делает: в путях Windows кавычек быть не может. «Security fix» в release notes — громко сказано.
- Exit code `pgn-extract` при конвертации не проверяется.
- Много строк в `AnalysisDlg.cpp` и справке `ResultsDlg.cpp` без `Loc(...)` — в русском интерфейсе они на английском.
- `Setup/Setup.vdproj` ссылается на Stockfish 7/8 и .NET 4.5 — устарел.
- `CStats::AddPosition` вставляет в отсортированный `CArray` — O(n²) на больших базах. Сортировка не нужна вовсе.
